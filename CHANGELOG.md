# Changelog

## 1.0.0 (2026-11-18): first release
- Playground (full-screen agent chat with source citations, knowledge on/off, history)
- WhatsApp connections: Evolution API v2 (QR), Meta Cloud API, generic gateway, sandbox + simulator
- Inbox: three-pane view, per-chat agent, Auto / Draft first / Off, approve/edit/discard drafts, take over/resume, ask agent, rules
- Reply pipeline: dedupe, opt-out, handoff keywords + model-requested handoff, business hours + away message, per-number rate limit, human-like delay
- Knowledge: PDF/DOCX/XLSX/CSV/TXT/MD, single web page, Q&A; background indexing; BM25 retrieval per agent
- LLM: OpenAI, Anthropic, Gemini, DeepSeek, Qwen, any OpenAI-compatible; per-agent override; hidden platform default with fallback
- Settings: general (hours, theme), models & keys, agents + defaults, WhatsApp, team & invites, usage, security (retention, export, audit, password)
- Dark and light themes; 25 automated tests; Docker + Compose (with Evolution API)

## 1.1.0 (2026-11-18): Vue frontend
- **New `frontend/`: Vue 3 + Vite + Vue Router single-page app** replacing the Flask-rendered pages. All 11 screens ported with the same design and dark/light themes.
- Flask is now **API-only**: templates, static files and page routes removed. All responses (including 404/405) are JSON; `GET /` returns service info.
- New `FRONTEND_URL` setting (invite links point at the Vue app).
- Deployment: `web` container (Node build → nginx serving the SPA and proxying `/api` + `/webhooks`) in front of the `api` container. One origin, so cookie auth and CSRF are unchanged.
- `frontend/scripts/check.py`: static checks of the Vue sources that run without npm; included in `make test`.
- 2 new backend tests (JSON-only responses, invite links): 27 total.

## 1.1.1 (2026-11-18)
- `requirements.txt` uses version ranges instead of exact pins, so installs work on Python 3.9–3.13
  (exact pins like `requests==2.34.2` required Python 3.10+). Supported Python range documented.
- `frontend/scripts/check.py` made Python 3.9-compatible.

## 1.1.2 (2026-11-18)
- Makefile no longer assumes a `python` command: it uses `.venv/bin/python` when present, else `python3`
  (override with `PYTHON=`). New `make venv` target. Docs use `python3` throughout.

## 1.1.3 (2026-11-19)
- Passwords are hashed with PBKDF2-SHA256 (600k iterations) instead of Werkzeug's default scrypt, which
  is missing on Pythons linked against LibreSSL (macOS system Python 3.9) and broke registration/login.
  Existing hashes still verify. New test runs registration/login with `hashlib.scrypt` removed.

## 1.1.4 (2026-11-19)
- Dev API port moved from 5000 to **5001** (`make api`, Vite proxy, default `PUBLIC_BASE_URL`): on macOS the
  AirPlay Receiver owns port 5000 and returned 403 to every login. Tests no longer hard-code the base URL.

## 1.1.5 (2026-11-19)
- **UI:** the left menu (and the Settings sub-menu) is pinned to the window and no longer scrolls with the page;
  only the Playground's recent-chats list scrolls inside it. Playground and Inbox now fill the window, with the
  conversation scrolling in its own panel and the message box always visible.
- New test: every API call in the Vue app must match a Flask route.

## 1.1.6 (2026-11-19)
- **API documentation** (replaces the endpoint diagram): `docs/API_BACKEND.md` (all 64 endpoints with
  parameters, body fields, real example requests/responses, errors), `docs/openapi.json` (OpenAPI 3.0) and
  `docs/API_FRONTEND.md` (Vue client, session, utils, composable, components, routes, calls per screen).
  Generated by `scripts/gen_api_docs.py` (`make api-docs`); `tests/test_api_docs.py` keeps them complete.

## 1.1.7 (2026-11-20)
- **The app now says when it isn't really working, and why.**
  - A banner appears when the browser can't reach the Flask API, and says what to check: the Vite proxy getting
    no answer, or AirPlay answering on port 5000. Before, this just showed "Request failed (500)".
  - A "Demo mode" card in the sidebar appears while replies come from the placeholder model or only sandbox
    WhatsApp numbers exist, with links to fix each. `GET /api/me` now returns `setup {model_ready, real_whatsapp}`.
- **Saving the first real API key starts using it.** Before, the workspace stayed on "Platform default", which is
  the placeholder model in development, so nothing changed. The key's provider and a starter model are now selected
  automatically.
- A failing workspace key no longer falls back silently to the placeholder model (which produced "(mock)" answers
  that looked like real ones); the provider's error is shown instead. Falling back to a *real* platform model still works.
- `make doctor` (`scripts/doctor.py`) checks API, Vue dev server, proxy, database, model and WhatsApp setup, and prints fixes.

## 1.2.0 (2026-11-20)
- **New look, matching the mother project AI Wonder Lab (aiwonderlab.tech).**
  - Black and white with one mint accent, Space Grotesk headings over Inter text.
  - Pill buttons and segmented controls (the chosen option filled in ink), 20px cards, mint for agent replies.
  - The lab's ring logo with a breathing mint core (`BrandMark.vue`, also the favicon), and calm motion that
    switches off for reduced-motion users.
  - The sign-in page gets the lab's big heading over a field of dots.
  - Light mode is now the default before the theme loads; system preference and the saved choice still apply.
- All colours are still tokens in `frontend/src/styles/app.css`. `--pri` is now ink (near-black on light,
  near-white on dark): text on it uses `--on-pri`, never a fixed white.

## 1.3.0 (2026-11-20)
- **Production-ready defaults: no mock data.**
  - Removed the demo seed (`scripts/seed_demo.py`, `make seed`, demo login) and the screenshot script
    that depended on it. A new install starts empty: open the app and create your workspace.
  - No placeholder model by default (`PLATFORM_LLM_PROVIDER` is empty). Without a model, agents say
    "No AI model is set up yet…" instead of sending "(mock) …" text.
  - Sandbox numbers, the Simulate button and the `mock` model are now **test tools**, behind
    `ENABLE_TEST_TOOLS` (default off). The automated tests turn them on.
  - The sidebar card is now "Finish setup"; the Playground chip says "Test chat · not sent to WhatsApp".
- Evolution: inbound messages older than 5 minutes (history replayed when a number links) are ignored.

## 1.3.1 (2026-11-20)
- **VPS deployment** (`deploy/vps/`, guide in `docs/DEPLOY_VPS.md`):
  - `make deploy VPS=root@<ip> DOMAIN=…` copies the project, creates `.env` with fresh secrets on the first run,
    builds, starts and health-checks the stack.
  - Agentry listens on 127.0.0.1:8090 behind the host's Caddy.
  - Daily database backup (14 kept) and data-retention job.
- `frontend/.dockerignore`, and a tighter root `.dockerignore`.

## 1.4.0 (2026-11-20)
- **Plain Docker Compose, ready for GitHub.** `git clone`, then `scripts/init-env.sh your.domain`,
  then `docker compose up -d --build`.
  - Replaces the push-over-SSH scripts in `deploy/vps/`.
  - The app is published on `127.0.0.1:8090` (`AGENTRY_BIND` / `AGENTRY_PORT`).
  - Evolution API is an optional Compose profile, with its passwords taken from `.env`.
  - New `scripts/backup.sh`.
- `.gitignore` keeps `.env`, keys, databases, `node_modules`, `.venv` and local scratch out of the repository.
- GitHub Actions CI (`.github/workflows/ci.yml`): pytest, API-doc completeness, Vue production build,
  Docker build and health check.
- API healthcheck starts faster, so `web` waits for a healthy `api`.

## 1.4.1 (2026-11-20)
- Frontend image: build stage uses `node:22-slim` instead of `node:22-alpine`. On Alpine, Rollup fails with
  "Code is nested too deeply" while bundling Vue. The served image is still `nginx:1.27-alpine`.

## 1.4.2 (2026-11-20)
- nginx answers 404 to dotfile and config-file probes (`/.env`, `/.git/config`, `*.sql`…) instead of the app page.
- On a server, the "Can't reach the API" banner points to `docker compose ps` / `logs` instead of `make api`.

## 1.4.3 (2026-11-20)
- **WhatsApp privacy IDs (LID).** Evolution messages that come from a `…@lid` sender are no longer
  treated as phone numbers, which made every reply fail with `exists:false`. Agentry now uses the real
  number when Evolution provides it (`senderPn` / `remoteJidAlt`), and otherwise replies to the LID JID
  itself. The Inbox shows "Private number" for such contacts.
